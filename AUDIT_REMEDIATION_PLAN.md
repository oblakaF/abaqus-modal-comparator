## 1. Договорённость о способе работы

- **Один исполнитель — агент VS Code.** Одна рабочая ветка/дерево, один *законченный функциональный пункт за один английский промпт*, а не последовательность мини-заданий. Агент сначала проверяет Git/фактический код, затем реализует пункт, запускает профильные тесты и доступную регрессию, делает реальный Windows smoke через \`RUN_PROGRAM.cmd\`, commit/push и **STOP**. При дефекте после проверки — адресное исправление в *этом же пункте*, не новый этап.
- **Владелец принимает результат каждого пункта.** Отчёт агента — не приёмка. Проверяются точный SHA, parent, diff, ветка, CI для SHA, фактический код, тесты (PASS / FAIL / SKIPPED / NOT_RUN) и Windows GUI. Только после вердикта \`ACCEPT\` переходим к следующему пункту. Не повышать статусы самостоятельно.
- **Статусы в этом файле меняются только после приёмки владельцем.** Исполнитель не ставит себе \`ACCEPT\`.
- **Нет автоматических PR/merge.** Не создавать PR, не объединять с \`main\`, не пушить в \`main\` без отдельного разрешения. Никаких force-push, reset --hard, git clean, удаления данных, переписывания истории. Сохранить существующие неотслеживаемые файлы.
- **Без Abaqus / новых FE / реальной LM/Auto-ID идентификации** без отдельного явного разрешения владельца. До такого разрешения — код, синтетика, готовые FE/EXP только для read-only просмотра/диагностики.
- Не менять \`docs/auto_id/SPEC_V1_2.md\`, \`SPEC_V1_1.md\`, \`DECISIONS.md\`, \`STATUS.json\`, frozen evidence, принятые регистрации, научные пороги и gates без отдельного решения владельца. **M8 GATE NOT_MET; D-077 NO_GLOBAL_PARAMETER_VALUE; production Auto-ID BLOCKED.**
- Ориентация определяется **независимыми** физическими сведениями (сторона, оси, геометрические ориентиры), **не** максимизацией MAC/совпадения частот. MAC — проверка форм/пар и отслеживание ветвей; **не** целевая функция определения материала. Экспериментальная мода №1 не исключается автоматически. Жёсткотельные FE-моды — по принятому критерию формы, не по частотному порогу.
- Синтетический PASS, численная сходимость, реальный Windows smoke, физическая подтверждённость и научная приёмка — разные утверждения.

## 2. Доказанная исходная позиция

1. **F1/F2**: устранение устаревших результатов Solid What-If подтверждено проверкой основного запуска \`RUN_PROGRAM.cmd\` в Windows (24/24 заявленных GUI-проверок на 100% и 150% через \`QT_SCALE_FACTOR\`); локальные материалы проверки доступны агенту, но не хранятся в GitHub. Не переделывать этот маршрут без необходимости.
2. **Новый GUI**: \`RUN_PROGRAM.cmd\` без \`legacy\` запускает \`RUN_NEW_GUI.cmd\`. Уже существуют загрузка FE/EXP, просмотр форм, частотная диагностика, экспорт, \`Set up registration\`, draft → human confirmation → сравнение с MAC при подтверждённой регистрации.
3. **Геометрия**: \`reviewed_core.geometry_alignment_candidates\` ограничен перестановками/знаками осей; \`services.generic_registration\` уже умеет произвольный 3D rigid fit по физическим ориентирам, в том числе поворот 45°. Нельзя считать, что произвольного поворота в программе нет совсем.
4. **Research Tuning**: \`services.research_frequency_tuning.observations_by_rank\` перенумеровывает оставшиеся частоты после EXCLUDED; встроенная \`_first_mode_check\` уже сохраняет ранги остальных. Порог \`MISFIT_RMS = 0.02\` сейчас создаёт предупреждение, но не запрещает \`NUMERICALLY_SUPPORTED\`. Это конкретная опасность неправильной интерпретации.
5. **ROTATED**: 11 fitted PolyMAX modes, 289 measured points; эксперимент ROTATED от 27.10.2026 и модель M11 серии 16.10.2026 **не подтверждены как тот же физический образец**. Для физической регистрации не хватает независимо подтверждённых осей/поворота, измеренной стороны, ориентиров и/или сведений об образце. Близость 18.63 и 19.07 Hz не есть подтверждение пары.
6. **Аудиторская Ritz-оценка** \`E1≈58.0, E2≈43.0, G12≈4.72 GPa\` (ν12=0.17, h=0.875 mm, mass=118.37 g; RMS ~2%) — только внешний условный исследовательский ориентир. **Не** эталон, acceptance target или физически подтверждённые константы. Внешний аудит не запускал реальный Windows GUI, не имел оригинальных ODB/INP; полного независимого воспроизведения его расчётов в репозитории нет.
7. **CI**: GitHub Actions на \`74be1e8\` красный; Linux-тесты \`test_solid_forward_runner\`/Solid GUI проваливались и на родительском коммите, в полном прогоне присутствует авария \`bool_dealloc\`. Это отдельно от принятых Windows F1/F2.

### ABM-AUD-1 — Research Tuning без ложного соответствия и ложного «успеха»

**Объём за один промпт:** найти владельца кода; исправить/проверить поведение \`FIT\`/\`HOLDOUT\`/\`EXCLUDED\` так, чтобы исключение наблюдения не сдвигало **неявно** прежние соответствия других мод (явная карта имеет приоритет); первая экспериментальная мода по умолчанию сохраняется; отсутствие доказанного соответствия нельзя молча лечить перенумерацией. Разделить сообщения «оптимизатор сошёлся», «модель объясняет спектр» и «материал идентифицирован». Для большой невязки (в т.ч. ~16%) не показывать безоговорочно «хороший» кандидат; сохранить численные результаты для диагностики с явным \`HIGH_MISFIT\`/аналогичным смыслом и предупреждениями. Проверить связанные результаты GUI и экспорт. **Не менять значение 2% или governed scientific gates**; если нужен новый запрет выдачи кандидата, зафиксировать требуемое решение владельца, а не вводить скрытно. Сохранить явный метод соответствий, мультистарт, holdout и предупреждения.

**Приёмка:** синтетические тесты на исключение первой и средней моды, неизменность рангов остальных, явное соответствие, holdout, высокий RMS, связанные статусы/экспорт; \`tests/test_real_fit_r1_tuning.py\`, \`tests/test_real_fit_r2_stability.py\`, профильные GUI-тесты; Windows GUI Research Tuning через \`RUN_PROGRAM.cmd\` без solver/реального fit. Исправление должно быть понятным пользователю на одной странице. Критерий — отсутствие вводящего в заблуждение «численно подтверждено» при плохом совпадении, а не получение желаемых модулей.

### ABM-AUD-5 — Быстрая исследовательская оценка пластины на существующих сервисах

**Объём за один промпт:** полный маршрут \`measured PolyMAX modal set + реальные/заявленные размеры, масса, толщина, ν12 + регистрация и объявленные/проверяемые модальные соответствия → Ritz → bounded fit → FE-input research estimates\`. Использовать формы Ritz на измеренных DOF для проверки соответствия и отслеживания ветвей, **не** как целевую функцию MAC и **не** как способ выбора поворота. Зафиксировать пары перед оптимизацией; контролировать близкие моды/потерю ветвей, держать первую экспериментальную моду. Отдельно показывать изгибные жёсткости D11/D22/D66, E1/E2/G12 только условно при фиксированных h, mass и ν12, неустановленную ориентацию E1↔E2 не разрешать по одной частоте. Реальный LM/Auto-ID и новое Abaqus — только после отдельного разрешения.

**Приёмка:** синтетическая восстанавливаемость, неверные/missing pairs → refusal/diagnostic, фиксированное ν12, swapped axes, near-degeneracy, положительная определённость и сохранение ветвей; Windows GUI работает без FE solve. Значения 58/43/4.72 и RMS 2% **сравнительная гипотеза, а не тест с обязательным PASS по цифрам**.

### ABM-AUD-7 — FRF и модальная метаинформация (после основного пути)

**Объём за один промпт:** вначале проверить, что реально есть в сырых FRF и PolyMAX-файлах (для ROTATED есть отдельный FRF-файл; в PolyMAX UNV dataset 58 отсутствует); правильное сохранение damping и modal A/B только с подтверждённым смыслом формата, без выдуманных коэффициентов. Балка, труба, сэндвич — **расширение возможностей**, не дефект реализации плоской Ritz-пластины. Не развивать универсальный C3D8I с Tie и множеством материалов вместо Abaqus. ## 5. Что считается завершением основного плана (ABM-AUD-1…6)

Пользователь запускает \`RUN_PROGRAM.cmd\`; на готовых FE/EXP данных видит реальные частоты и формы. При достаточной независимо подтверждённой геометрии получает воспроизводимые пары и MAC, в том числе диагностику близких мод; при её отсутствии — честную диагностику без выдуманного MAC. Исследовательская функция Ritz на соответствующих допустимых данных считает и показывает условные D и E с явными допущениями/чувствительностью, но не выпускает материальных констант и не изменяет Auto-ID. Результат можно сохранить, открыть и экспортировать. Есть Windows smoke и различимые PASS/FAIL/SKIPPED/NOT_RUN; CI восстановлен или известный блокер честно отмечен.
